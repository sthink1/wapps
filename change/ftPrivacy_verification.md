## Limitations and release implications

- **Browser workflow gap:** The unchanged `httpdocs/js/FTOneTreeMerge.js` does not forward `X-FT-Page-Token` or offer a privacy-code prompt. A regular user encountering a private subject will now receive HTTP 423 even if they previously unlocked it on a different page. This is intentional fail-closed protection, but full code-enabled browser merge-review acceptance remains OPEN. **Do not treat this ZIP alone as full M03 release closure.** A separately approved, minimally scoped browser integration may be necessary.
- The review protection checks derived data in One Tree preview responses; it does not change validation of the One Tree **merge POST** or other Family Tree APIs. No claim of full route-wide privacy security is made.
- Current production/staging commit equivalence and hosted behavior were not independently tested. Verify installed source baseline before replacing; execute controlled local acceptance before any commit, merge or deployment.
- The pre-existing `redactPerson` intentionally preserves Person name and FamilyTreeCode fields as existing WA behavior. This package does not change that broader disclosure policy.
